AI LAB · CYBERSECURITY

SafeClick AI: Phishing Awareness and Account Safety Assistant

A privacy-conscious custom GPT that gives calm, defensive guidance for suspicious messages and exposed accounts.

Purpose

Help nontechnical users recognize phishing warning signs, avoid unsafe actions, and contact official support.

Skills Demonstrated

Prompt design, GPT Builder, design thinking, privacy safeguards, scenario testing, and responsible AI boundaries.

Evidence and Process

Five realistic scenarios were documented; four passed and one platform safety block was recorded transparently.

Learning Outcomes

Useful AI guidance requires clear limits, honest uncertainty, privacy protection, and human escalation.

Open artifact evidence ↗
REFLECTION

What I learned and how I will apply it

Creating SafeClick AI helped me understand that a useful generative AI tool begins with a clearly defined user problem rather than with the technology itself. I practiced writing focused instructions, protecting private information, communicating uncertainty, and testing how the assistant responded in realistic phishing situations. My strongest contribution was combining my cybersecurity background with calm language and practical actions that an everyday user could follow.

This artifact also showed me that responsible AI requires boundaries and human judgment. The assistant could identify warning signs and recommend defensive steps, but it could not verify a sender, inspect a device, or guarantee that an account was secure. In future work, I would involve independent users, create a formal evaluation rubric, and continue improving escalation guidance so the tool remains helpful without encouraging overreliance.

COMPARATIVE ANALYSIS · MODEL CHOICE

Machine Learning vs. Deep Learning

A practical decision guide using credit-risk prediction and skin-cancer image analysis.

Purpose

Explain when structured-data machine learning or deep learning is the stronger fit for a real problem.

Skills Demonstrated

Academic research, technical writing, model selection, data analysis, and explainability reasoning.

Evidence and Process

Peer-reviewed cases compare feature engineering, data needs, computation, transparency, and operational context.

Learning Outcomes

The strongest model fits the data, risk, resources, and decision instead of simply being the most complex model.

Open artifact evidence ↗
REFLECTION

What I learned and how I will apply it

This comparison strengthened my understanding that machine learning and deep learning should be selected according to the problem and the form of the data. Credit-risk prediction showed why traditional machine learning can be valuable when variables are structured and leaders need to explain a decision. Skin-cancer image analysis showed how a convolutional neural network can learn complex visual patterns that would be difficult to define manually.

The artifact improved my ability to translate technical differences into practical guidance for a nontechnical audience. I learned to consider explainability, data volume, computing requirements, risk, and operational context before recommending a method. To strengthen this work in the future, I would add a small Python benchmark that compares accuracy, training time, and interpretability so the recommendation is supported by both research and measured evidence.

Adaptive Neural Network: Learning From a Changed Reality

A Python experiment showing performance loss after data changes and recovery after retraining.

94.4%Original environment
81.7%After change
95.0%After retraining
Purpose

Connect neural-network adaptation to problem solving, faith, communication, and change leadership.

Skills Demonstrated

Python, scikit-learn, ANNs, ReLU, synthetic data, concept drift, ethics, and model evaluation.

Evidence and Process

The measured accuracy drop and recovery show why models and organizations must monitor changing conditions.

Learning Outcomes

Leaders should preserve the mission while changing the method, communicating clearly, and maintaining accountability.

Open artifact report ↗ View Python code ↗ View results ↗
REFLECTION

What I learned and how I will apply it

The Python experiment helped me see how neural networks mirror the challenge of adapting to a new reality. The model performed well in its original environment, lost accuracy when the data changed, and recovered after retraining. This result reminded me that both models and leaders can become less effective when they rely only on past experience. Effective problem solving requires monitoring, feedback, learning, and a willingness to adjust the method.

Nehemiah 4 provides a meaningful example of adaptive leadership because the mission stayed the same while the strategy changed in response to new threats. Clear communication helped the people understand both the challenge and their responsibility. In AI/ML leadership, I will apply the same approach by explaining changes honestly, keeping people involved, and maintaining ethical oversight. I would improve this experiment with repeated trials, fairness checks, and defined drift thresholds.
